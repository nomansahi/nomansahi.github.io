CASE STUDY / OBSERVABILITY

When a quiet alert hides a failure.

The inherited expression checked only probe_success == 0. When collection failed and the result disappeared, the alert could return no series and stay quiet.

The correction

  • Report HTTP probe failure when scraping succeeds.
  • Report scrape failure when Prometheus cannot collect results.
  • Report a missing probe result when scraping succeeds but the expected metric is absent.

Evidence

Three alert rules were checked with eight independent promtool scenarios, including recovery, flapping, missing results, and simultaneous instance failures. Live experiments stopped the exporter and application, changed the HTTP target, and deliberately dropped a metric.

Operational context

The lab adds request rates, errors, histogram latency, process and filesystem metrics, SQLite measurements, structured JSON logs, a Grafana export, and an incident runbook.

A local learning lab, not a production service. SLOs are proposed; 30-day compliance, external notifications, and distributed tracing are not demonstrated. The application was developed with AI assistance and verified through local execution.

CASE STUDY / DELIVERY

A delivery pipeline with deployment evidence.

Started with an instrumented application in Minikube, then imported its namespace, Deployment, and Service into Terraform. A matching plan confirmed there were no unintended changes.

What was verified

  • Terraform scaling to two local application replicas.
  • ReplicaSet replacement after deliberately deleting a pod.
  • Three behavior tests covering health, correlated error logs, and SQL failures.
  • Publishing the tested container image to GHCR with its commit SHA.
  • Deployment through Terraform into a temporary CI cluster, followed by HTTP and database checks.

Monitoring and a startup lesson

Prometheus discovers both application pods through namespace-scoped permissions. Grafana uses persistent storage and a provisioned data source. An overly short liveness window restarted Grafana during initialization; a startup probe resolved that observed rollout failure.

The CI cluster is temporary and does not deploy to a persistent production environment. Local replicas share one node. Each application pod has temporary SQLite data. The imported Kubernetes dashboard still needs data-source adaptation; monitoring is not presented as complete.
